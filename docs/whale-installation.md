# 웨일 프로토타입 설치 안내

Desktop Whale용 **미출시 호환성 프로토타입** 안내입니다. 공개된 Chrome 웹 스토어 `0.1.0`과 구분하며, 본문 번역의 동등 지원이나 웨일 스토어 제출 준비 완료를 뜻하지 않습니다. 현재 패키지 버전은 `0.1.0` 그대로입니다. 이번 작업에는 버전 변경·웨일 스토어 제출·공개가 포함되지 않습니다.

## 설치

Node.js와 npm이 설치된 저장소 루트에서 실행합니다. 개발 기준 Node.js는 `22.23.2`입니다. 공통 설치 환경은 [개발 안내](development.md#로컬-설치-및-실행)를 따릅니다.

```bash
npm ci
npm run build:whale
```

1. 기존 사용 환경과 구분되는 개발용 Whale 프로필을 엽니다. 일반 프로필의 설정·저장값을 지우지 않습니다.
2. 주소창에 `whale://extensions`를 입력하고 **개발자 모드**를 켭니다.
3. 압축해제된 확장 프로그램 로드를 선택하고 저장소의 `.output/whale-mv3` 폴더를 지정합니다. `.output/chrome-mv3`나 ZIP 파일 자체를 선택하지 않습니다.
4. [Mountain Project](https://www.mountainproject.com/)를 열거나 기존 페이지를 새로고침합니다.
5. 설정을 저장한 적이 없으면 OFF와 첫 실행 안내가 표시됩니다. 페이지 상단 **확장 기능** 스위치를 켭니다. 저장된 ON/OFF가 있으면 기존 값을 유지합니다.

이 확장은 툴바 팝업 방식의 MV3 확장입니다. Whale 전용 사이드바 기능을 추가하지 않습니다. 코드 변경 후에는 다시 `npm run build:whale`를 실행하고 확장 관리 화면에서 해당 확장을 새로고침한 뒤 Mountain Project 페이지도 새로고침합니다. 공통 소스를 수정했다면 Chrome·Firefox 회귀도 변경 범위에 맞게 확인합니다.

## 활성화와 번역 제한

첫 실행은 설치 시점이 아니라 `storage.local.enabled` 키 부재로 판단합니다. 과거 설치라도 키가 없으면 OFF와 안내를 적용합니다. 설정 저장이 반영되면 강조 안내가 사라지지만 이는 언어팩 준비나 본문 번역 성공을 의미하지 않습니다.

메인·본문 번역 지원 페이지의 상단 ON 입력은 설정 저장을 기다리기 전에 번역 준비를 시도합니다. 메인은 준비만 하며 본문 컨트롤러·준비 실패 안내·일반 입력 재시도를 제공하지 않습니다. 본문 지원 페이지는 사용자 활성화가 더 필요한 경우 다음 일반 클릭·키 입력으로 다시 시도합니다. 팝업에서 ON으로 바꾼 입력이 콘텐츠 페이지의 사용자 활성화까지 보장하지는 않습니다.

Whale이 Chromium 기반이고 Papago를 제공해도 `Translator` API의 영어→한국어 번역이 가능하다는 뜻은 아닙니다. API 존재와 언어 쌍 가용성, 실제 콘텐츠 스크립트에서의 동작을 구분해야 합니다. 엔진을 사용할 수 없거나 준비가 실패하면 본문은 원문을 유지하고, 고정 UI 현지화와 지원되는 탐색 기능은 별도로 동작합니다. [번역 런타임](translation-runtime.md#whale-호환성-경계)에 구현 경계를 설명합니다.

Papago는 확장의 번역 엔진이나 대체 서비스가 아닙니다. 확장 자체 검증은 개발용 프로필에서 Papago 페이지 번역을 끈 조건과 켠 조건을 구분합니다. 켠 조건에서는 중복 번역·DOM 충돌 여부를 별도로 살펴봅니다. 일반 사용자 프로필의 Papago·플래그·브라우저 설정을 자동 변경하지 않으며, 비공개 API나 외부 번역 서비스를 추가하지 않습니다.

## ZIP과 배포 기록

```bash
npm run zip:whale
```

타입 검사 후 MV3 빌드, 공통 패키지 검사와 content script 실행 검사를 수행하고 실제 ZIP 내용도 검사합니다. 현재 버전의 일반 ZIP 경로는 `.output/mountain-project-korea-extension-0.1.0-whale.zip`입니다. 별도 폴더에 압축을 풀고 그 폴더를 로드하면 해당 ZIP 내용을 직접 확인할 수 있습니다. 일반 ZIP 생성은 배포 기록이나 스토어 업로드를 만들지 않습니다.

커밋이 정리된 소스를 별도 배포 준비 기록으로 묶는 명령은 다음과 같습니다. `0.1.0`은 현재 패키지 버전이며, 나중에는 실제 준비한 버전으로 바꿉니다. 이 안내 때문에 버전을 올릴 필요는 없습니다.

```bash
npm run release -- prepare --browser whale
npm run release -- verify 0.1.0 --browser whale
```

`prepare`는 깨끗한 작업트리와 package·lockfile·CHANGELOG의 버전 일치를 요구합니다. 의존성 설치, 타입 검사, 배포·패키지 검사 테스트, 전체 Vitest, `zip:whale`와 ZIP 검사를 모두 통과한 뒤 `.output/releases/whale/0.1.0/`에 ZIP·`release.json`·`CHECKLIST.md`를 생성합니다. 같은 버전 폴더를 덮어쓰지 않습니다.

신규 기록은 schema 2로 `browser: "whale"`, 버전·Git 커밋·ZIP SHA-256·파일별 해시·자동 검사 목록을 담고 Chrome 스토어 ID는 포함하지 않습니다. `prepared`는 로컬 자동 준비 상태일 뿐 실제 Whale 검증이나 제출 승인이 아닙니다. `verify`는 현재 소스와 기록·ZIP을 대조하며 테스트를 다시 돌리거나 수동 체크리스트 완료를 판단하지 않습니다.

Chrome은 기존 `.output/releases/<버전>/` 경로와 기본 명령을 유지합니다. 기존 schema 1 Chrome 기록은 검증할 수 있지만 Whale 기록으로 사용할 수 없습니다. 상세 중단 조건과 수동 단계는 [브라우저별 배포 절차](development.md#whale-기록-분리)를 따릅니다.

## 검증 결과와 정리

브라우저 정확한 버전·실행 환경, 설치·온보딩·번역 엔진·원문 유지·팝업·OFF 복원, Papago 조건, 자동 빌드·ZIP 결과는 [웨일 검증 기록](whale-validation-2026-10-01.md) 한 곳에서 관리합니다. 초기 화면 확인과 전체 기능 통과를 구분하고 이전 Chrome 검증 수치를 Whale 검증으로 재사용하지 않습니다.

작업 후 개발자가 만든 창·탭·임시 프로필만 정리하며 사용자의 기존 브라우저 세션은 닫지 않습니다. 확장을 제거하려면 개발 프로필의 `whale://extensions`에서 해당 항목을 제거합니다. `.output/` 산출물은 Git에 보관되지 않으므로 필요한 검증 증거와 패키지는 별도로 보관합니다.
