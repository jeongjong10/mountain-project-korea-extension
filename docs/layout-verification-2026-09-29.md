# 2026-09-29 레이아웃 확인

## 확인 방식

Codex 내장 브라우저는 확장 적용 화면을 검증하는 용도로 사용하지 않았다. Windows Computer Use 도구는 작업 폴더 URI 오류로 초기화되지 않았다.

초기 문제 재현은 별도 Chromium에 출력 스크립트를 직접 주입해 진행했다. 최종 확인은 별도의 임시 프로필에 `.output/chrome-mv3`를 unpacked 확장으로 로드해 진행했다. 웹페이지에 스크립트를 직접 주입하거나 `chrome.storage`를 모의 구현하지 않는다. `chrome-extension://` 실행 컨텍스트를 확인하고, 실제 확장 스위치로 ON/OFF를 바꾼다. 사용자 Chrome 프로필·로그인 정보에는 접근하지 않는다.

## 수정

대한민국 Area의 난이도 차트는 넓은 화면에서 렌더링한 457px 폭을 창 축소 후에도 유지했다. 390px 화면에서 확장 적용 시 문서 가로 넘침이 147px 발생했다. 적용 전 원본 사이트도 동일한 리사이즈 순서에서 97px 넘침이 있었다.

`#route-chart`와 `#rating-chart`의 바깥에 키보드로 접근할 수 있는 가로 스크롤 영역을 둔다. 차트 노드·데이터·원본 높이·이벤트는 유지한다. SVG 기준선과 접근성 보조 표가 차트 아래로 조금 확장되는 공간도 확보해 불필요한 세로 스크롤을 막는다. 기능 OFF 시 추가 영역을 제거하고 차트를 원래 위치에 돌려놓는다.

## 범위와 근거

- 실제 공개 페이지: MP 메인, 대한민국 Area, Chouinard B Route, Route Guide.
- 화면 폭: 1440·1024·768·390px. 페이지를 넓게 연 뒤 축소하는 순서도 포함.
- 문서 가로 넘침, 핵심 컨테이너 폭, 추가 SVG 아이콘 부재, ON/OFF 재적용, 섹션 펼치기·Enter 접기, 차트 방향키 스크롤을 확인.
- [최종 브라우저 기록](../design/review/2026-09-29/verified/live-layout.json)과 [소스·빌드 검증 기록](../design/review/2026-09-29/verification.json).
- [확장 로드 검증 스크립트](../design/check-installed-layout.mjs). 임시 프로필의 검증용 Chromium이며 사용자의 일반 Chrome과 같은 환경이라고 가정하지 않는다.

Firefox는 빌드와 출력 번들 smoke 검사 범위다. 사용자 Chrome 프로필, 로그인 동작, 200% 확대, 모든 하위 페이지·지도 동작·번역 품질에 대한 전수 검증은 남아 있다. 이 기록만으로 D7/D8 전체 완료나 출시 준비 완료를 표시하지 않는다.

## 최종 결과

4개 페이지 × 4개 화면 폭에서 확장 ON 및 재적용 후 문서 가로 넘침은 모두 0px이었다. 차트는 방향키로 40px 이동했고 스크롤 영역의 표시 높이와 콘텐츠 높이가 모두 107px로 같아 불필요한 세로 스크롤이 없었다. 관련 테스트 41개와 타입 검사를 통과했다. 이 검사는 마지막 CSS 하단 여백 조정 전에 수행했으며, 최종 Chrome·Firefox 빌드/번들 smoke와 실제 확장 브라우저 검사는 여백 조정 후 통과했다.

브라우저 기록에는 MP `ap-vendor-full.js`의 `globalEval`에서 `undefined.ready`를 참조한 예외 8건이 남아 있다. 원인은 확정하지 않았으며 콘솔 오류가 전혀 없는 실행이라고 보고하지 않는다. 공개 페이지의 레이아웃 검사를 위해 GET/HEAD 이외 요청을 차단한 환경이다.
