## 기술 검증의 증거와 한계

- **HTML 파서·조회:** 병렬 담당자가 실행한 [원본 결과 JSON 사본](evidence/privacy-directory-parser-2026-09-28.json)을 직접 읽었다. Chrome `149.0.7827.55`에서 현재 실제 TS 모듈을 번들해 main world와 CDP isolated world로 실행했다. 조회 URL만 로컬 시험 서버로 치환했으며 정상 문서 로딩을 양성 대조로 사용했다. 파서 경로에서 스크립트 실행 표식과 시험 리소스 요청은 0건, 양성 대조에서 이미지·iframe·CSS·스크립트 등 시험 경로가 관측됐다. 쿠키가 존재하는 양성 대조에서는 전송됐고 `omit` 조회에서는 두 실행 영역 모두 전송되지 않았다. 응답의 시험 `Set-Cookie`도 저장되지 않았다.
- **재현 범위:** 로컬 시험 HTML과 해당 Chrome 빌드에 대한 관측이다. CDP isolated world는 실제 설치된 확장의 전체 동작 검증을 대신하지 않는다. 모든 MP HTML, 향후 브라우저, 지도·통계 iframe 자체의 네트워크가 검증된 것은 아니다. 재현 도구는 검토 당시 `/tmp/mpkr-directory-parser-probe.mjs`에 있었고, 결과를 본 저장소에 사본으로 보존했다.
- **소스 동일성:** 시험 전후 해시가 같고 이번 검토에서도 현재 파일과 대조했다. `directory-counts.ts`: `f864be5ed2ef5a0bddf9cc6d4b2a45b387666ef15b692c348a0955e2fd43c8bb`; `origins.ts`: `c829d445826cf9c793f4f6791d2dcefe76fbef5dd05dc515418ff6c6d08c5782`; `routes.ts`: `0dd1ee4c284b529378de1e725e4a8bdb19b10032c5ba3204d45aa8f09bdf7974`. 결과 JSON SHA-256: `ad2c57f1b5af2531cd2f1ebc76c20407382d0fbb4b4677c84ddfdbb5f7c57ecf`.
- **iframe·OFF:** 병렬 담당자의 결과와 [지도 소스](../src/ui/south-korea-map-embed.ts), [통계 소스](../src/ui/route-stats-embed/layout.ts), [기능 해제 처리](../src/application/mountain-project-application.ts)를 대조했다. 지도는 처음 펼칠 때 생성, 다시 접을 때 유지, 통계는 mount 시 자동 생성하며 둘 다 `loading='lazy'`다. OFF는 추가 섹션을 제거한다. 제거가 이미 전송한 정보를 회수하거나 진행 중인 모든 네트워크 작업을 즉시 취소한다는 뜻은 아니다.

## 승인된 문의 삭제 운영

사용자는 **답변과 후속 확인 후 불필요한 문의 기록·첨부를 지체 없이 삭제하는 운영**을 승인했다. 이는 앞으로 지킬 운영 기준이며 이번 검토에서 실제 문의 메일을 삭제했다거나 과거 기록 정리가 끝났다는 뜻은 아니다.

1. 답변·후속 확인이 끝난 문의에서 더 필요하지 않은 메일과 첨부 사본을 특정한다. 다른 메일까지 포함하는 메일함 일괄 삭제는 이 절차의 대상이 아니다.
2. 대상 메일을 삭제한 뒤 휴지통에서도 영구 삭제하고, 따로 내려받은 불필요한 첨부 사본을 정리한다. Gmail의 일반 삭제는 최대 30일 동안 휴지통에 남으므로, 휴지통 이동만으로 즉시 정리했다고 기록하지 않는다. [Gmail 공식 삭제 안내](https://support.google.com/mail/answer/7401?hl=ko)
3. 처리 결과를 필요한 범위에서 안내한다. 삭제 증거를 남긴다는 이유로 원문·첨부를 새 문서나 작업카드에 복제하지 않는다. Google의 내부 백업까지 즉시 제거했다고 보장하지 않는다.

## 내부 출시 메모 — 아직 확인하지 않은 사항

- **Gmail의 법적 관계:** 현재 문서는 Gmail 사용과 Google의 여러 국가 서버 처리 가능성을 설명한다. 이는 실제 수탁자·계약 관계, 이전 국가·수신자·근거가 확정됐다는 의미가 아니다. [Google 방침](https://policies.google.com/privacy?hl=ko)은 세계 각지 서버 운영과 이메일 콘텐츠 처리를 설명하지만 이 프로젝트의 국내법상 분류를 대신하지 않는다. 계정에 적용되는 서비스 약관·계약, 실제 업무 처리 관계와 접근·보관 구조를 확인한 뒤 해당하는 고지와 절차를 판단할 항목으로 남긴다.
- **계정 보안과 사본:** 2단계 인증, 로그인 기기, 전달 설정, 위임 접근, POP/IMAP·외부 메일 클라이언트, 자동 백업·별도 첨부 저장 위치는 이번 검토에서 확인하지 않았다. 따라서 이를 이미 시행 중인 안전조치라고 방침에 쓰지 않았다. 삭제 운영을 적용할 때 개발자가 관리하는 사본의 범위를 확인해야 한다.
- **법률 검토와 CWS의 구분:** CWS 정책은 플랫폼 최소 기준이며 적용 법률을 대체하지 않는다. 국내법 적용 시 [제30조](https://www.law.go.kr/법령/개인정보보호법/제30조)의 목적·보유·파기·권리 행사 등과 해당되는 [제26조](https://www.law.go.kr/법령/개인정보보호법/제26조)의 위탁, [제28조의8](https://www.law.go.kr/법령/개인정보보호법/제28조의8)의 국외이전 근거·절차를 구분해 확인한다. 국외이전은 별도 동의만이 유일한 근거라고 단정하지 않는다. 이 검토는 해당 항목의 법적 적용이나 충족을 확정하지 않는다.
- **최종 게시·스토어 일치:** 개정 Markdown, 실제 공개 HTML, 최종 빌드와 스토어 개인정보 신고를 대조해야 한다. 이번 보고서의 검토 해시 이후 변경이나 공개 사이트 동기화는 해당 게시 담당자의 검증 결과로 확인한다. 공개 저장소의 fixture에 있는 사용자명·댓글은 확장 런타임 수집과 별도인 [소스 자산 검토](asset-and-attribution-review.md) 범위다.

이 검토에서 변경한 파일은 본 보고서와 시험 결과 JSON 사본뿐이다. 제품 코드, 개인정보처리방침 본문, 메일·계정 설정, 스토어 신고와 외부 발송은 변경하지 않았다.
