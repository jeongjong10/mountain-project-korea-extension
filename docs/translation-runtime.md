# 번역 런타임 명세

이 문서는 현재 로컬 소스의 자동 번역, 원문 보존, 재번역과 실패 복구 동작을 설명한다. 고정 UI 사전과 페이지별 DOM 계약의 세부 목록은 `src/sites/mountain-project/contract/`을 기준으로 한다.

## 경계와 처리 흐름

1. Mountain Project page adapter가 지원 DOM을 `DomTranslationTarget`으로 수집한다.
2. `PageTranslationController`가 페이지 종류·문맥·정책·용어집 버전을 포함해 번역 요청을 준비한다.
3. 번역 정책이 루트명·지역명·사용자명, 등급, URL, 이메일, GPS, 장비 규격을 토큰으로 보호한다. 일반 등반 용어와 구절은 원문 그대로 번역기에 전달한다.
4. 플랫폼 `TranslationProvider`가 영어에서 한국어로 번역한다. 현재 제품 provider는 Chrome 내장 `Translator` API를 사용한다.
5. `OriginalPreservingRenderer`가 원본 DOM을 보존한 채 번역본을 별도 렌더링하고, OFF 또는 destroy 시 원래 표시 상태를 복원한다.

공통 application과 core는 WXT 및 브라우저 전역 API를 직접 사용하지 않는다. 브라우저별 provider와 설정 저장소는 `src/platforms/`, WXT 조립은 `src/entrypoints/`에 둔다.

## 대상 모드

| 모드 | 현재 동작 |
| --- | --- |
| `block` | 설명·접근·댓글 같은 블록을 번역본으로 표시하고 원문 보기·재번역 컨트롤을 제공한다. |
| `inline-copy` | 작성자 주변의 댓글·등반 기록처럼 원본과 같은 문맥에 번역 복사본을 배치한다. 원문 보기·재번역 컨트롤을 제공한다. |
| `inline` | 짧은 제목 등 텍스트 노드를 직접 치환한다. 원문 전환·재번역 컨트롤은 제공하지 않으며 OFF 시 원문으로 복원한다. |

고정 UI 사전 치환은 기계 번역 대상과 별도다. User·Contributions·Community·Contact 페이지는 현재 고정 UI 중심이며, Help Hub의 Feature Request는 제목·설명의 번역 표시와 원본 데이터를 분리한다.

`/about`의 `#about-page`가 확인되면 소개·연혁 본문을 기존 도움말과 같은 인라인 번역 경로로 처리한다. 제목·통계 라벨은 사이트 계약 사전으로 번역하고 기여자·관리자 목록과 통계 숫자는 제외한다. 링크·강조·줄바꿈의 DOM 구조와 OFF 복원을 유지한다.

Help Hub에서 뒤늦게 생성되는 시작하기 카드 제목·설명과 주제 소개도 본문 번역에 포함한다. 기능 제안의 필터·모달·오류·완료 알림은 고정 UI이며 제안 제목·설명은 구조 보존 번역과 기존 원문 보기·재번역을 제공한다. 동적으로 교체되는 카드도 같은 MutationObserver 경로에서 수집하며 번역 복제본은 재수집하지 않는다. 작성자·댓글·투표 수·폼 입력값과 서버 원본 데이터는 보존한다. 카테고리 필터의 원문 문자열 비교와 제안 폼의 암묵적 option 값 때문에 `HelpHubLocalizer`가 기존 관찰 주기에서 선택 표시와 option의 표시용 `label`만 보정한다. 별도 polling이나 관찰자는 추가하지 않는다.

추가·편집·제안·공유·변경 내역 경로는 `contribution` 페이지 종류로 분류한다. 독립 기여 페이지뿐 아니라 Area 문서에 AJAX로 삽입되는 `/improvement/...` 모달도 `contract/selectors/contribution.ts`의 범위 계약으로 인식한다. 이 화면은 기계 번역 대상 수집을 실행하지 않고, `contract/text/contribution.ts`에 등록된 고정 라벨·안내문·버튼·placeholder만 직접 번역한다.

폼 안전성 규칙은 다음과 같다.

- 사용자가 작성한 `input`·`textarea`의 `value`와 편집기 내용은 변경하지 않는다.
- 서버가 제출값으로 사용하는 `input[type="submit"].value`는 번역하지 않는다.
- 명시적인 `value`가 없는 `option`의 텍스트는 제출값일 수 있으므로 번역하지 않는다. Help Hub의 `#hh-form-cat`만 별도 계약으로 표시용 `label`을 번역하고 원문 텍스트·value를 유지하며 OFF 시 label을 복원한다.
- 폼 `action`, `method`, `name`, hidden 값과 Mountain Project의 원래 이벤트·제출 흐름을 유지한다.
- 동적으로 추가된 개선 모달은 기존 `MutationObserver` 수명주기에서 처리하고 OFF 또는 destroy 시 번역한 표시 문자열과 placeholder를 복원한다.

## 자동 번역과 부하 경계

- 지원 대상은 페이지 진입 후 비동기로 자동 번역한다. 언어팩이 다운로드 가능한 상태이면 클릭 또는 키 입력 경계에서 다시 시작한다.
- 댓글은 `IntersectionObserver`가 있으면 화면에 보이거나 가까운 대상부터 처리한다.
- provider 호출은 컨트롤러의 단일 drain에서 순차 실행한다. 준비 큐는 한 번에 최대 32개를 꺼내고 이벤트 루프에 제어를 돌려준다.
- 프레임별 메모리 캐시는 최대 500개이며 키와 번역 합계가 524,288 UTF-16 코드 단위를 넘으면 오래된 항목부터 제거한다.
- 캐시 키에는 provider, 언어, 페이지·문맥, 정책·용어집 버전, 보호된 입력과 원문이 포함된다.
- OFF 또는 destroy 시 관찰자·표시 기록·캐시를 정리하고, 늦게 완료된 이전 세대의 결과는 화면이나 캐시에 적용하지 않는다.

## 원문과 재번역

- 번역이 성공한 블록형 presentation은 한국어를 기본으로 표시하고 `원문 보기`로 원본을 전환한다.
- `재번역`은 해당 presentation의 비인라인 대상을 묶어 캐시를 우회한다. 처리 중에도 현재 번역을 제거하지 않는다.
- 새 결과가 달라지면 한 번에 교체하고, 같으면 `동일한 결과`, 실패하면 `재번역 실패` 상태를 표시한다.
- 최초 provider 실패에는 원문과 실패 안내를 표시한다. 보호 토큰·DOM 구조 검사로 거부한 결과는 `preserved` 상태로 기록하고 원문을 조용히 유지한다. 해당 문단과 페이지 전체에 경고를 띄우지 않으며 기존 재번역 버튼은 유지한다. 자동 반복은 막고 사용자가 누른 재번역 한 번만 허용한다.
- 재번역에서 구조 검사가 다시 실패해도 경고나 실패 피드백을 표시하지 않는다. 이미 성공한 번역은 새 구조 검증이 끝나기 전까지 보존한다. 이후 provider 오류가 발생하면 일반 실패 안내와 재시도를 다시 허용한다.
- 재번역도 원본 사이트의 게시물·계정·URL을 수정하지 않는다. 결과와 상태는 현재 페이지·프레임 메모리에만 존재한다.

## 긴 댓글과 원문 형식

장문 댓글은 루트 레벨의 연속 `<br>`로 표현된 빈 줄에서만 문단을 나눈다. 중첩 목록·링크 내부의 줄바꿈은 분할점으로 사용하지 않는다. 각 문단은 원래 순서대로 번역하고 분리 기호를 그대로 결합한다.

번역문은 모든 문단이 성공하고 구조 토큰이 검증된 뒤에만 렌더링한다. 중간 문단 하나라도 실패하면 부분 번역을 노출하지 않고 전체 원문과 재번역 동작을 유지한다. 링크 목적지, 강조, 목록, 줄바꿈과 안전한 블록 구조는 원본 DOM에서 복제하며 스크립트나 임의 원격 마크업은 복제하지 않는다.

설명 등 구조화된 본문에서 보호 토큰 검증이 실패하면, 루트 레벨의 단일 `<br>`까지 경계로 삼아 더 작은 단위로 한 번 다시 시도한다. 실제 번역 구간 수가 늘어나는 경우에만 실행하며 중첩 링크·강조·목록 안은 나누지 않는다. 줄바꿈은 번역기로 보내지 않고 원래 위치에 결합한다. 모든 구간의 보호 값과 최종 구조 검증은 그대로 적용하고, 하나라도 실패하면 전체 원문을 유지한다. 성공한 복구 결과는 원래 요청의 캐시 키에 저장한다.

## 실패 안전성

보호 값·종류는 요청별 복원 목록에 유지하고, 모델에는 `ZXQ0QXZ` 형태의 짧은 식별자만 보낸다. 원문에 같은 형식이 있으면 접두사를 늘려 충돌을 피한다. 대소문자 차이만 허용하며 식별자의 숫자를 추측해 보정하지 않는다. 각 식별자가 정확히 한 번 존재하는지 확인하고 알 수 없는 식별자가 추가된 결과도 거부한다. 현재 정책 버전은 `mpkr-policy-5`, 용어 정책 버전은 `mpkr-climbing-ko-3`이다. 일반 용어의 강제 치환과 무조건 영문 보존은 제거했으며 DOM에서 확인된 이름과 기술 값·서식 보호는 유지한다.

- 번역 결과가 비어 있거나 원문과 같으면 성공으로 표시하지 않는다.
- 보호 토큰이 누락·중복·변형되면 잘못 복원하지 않고 결과를 폐기한다.
- 현재 Mountain Project 정책은 용어집 토큰을 만들지 않으므로 용어집 fallback 재호출도 발생하지 않는다.
- provider 미지원, 모델 준비 필요, 일반 실패를 구분해 원문을 유지한다.
- 동적 DOM이 바뀌면 target fingerprint와 원문을 비교해 새 revision만 처리하고, 연결이 끊긴 대상 기록은 제거한다.

## 검증 경계

자동 테스트는 controller, renderer, 형식 보존, 장문 댓글 fixture, 동적 DOM, OFF 복원과 플랫폼 경계를 다룬다. 실제 Chrome 언어팩의 번역 품질, 사용자 동작이 필요한 모델 시작, Mountain Project 운영 DOM과 iframe 동작은 배포 후보 빌드로 별도 수동 검증해야 한다.

기여 흐름 테스트는 경로 분류, 독립 추가 폼, Area에 동적으로 삽입되는 개선 모달, OFF 복원과 작성값·submit 값 보존을 검증한다. 로그인 계정에서 보이는 메뉴 항목 전체와 실제 저장·제출은 자동 테스트의 범위가 아니며 별도 실환경 검증 항목이다.

기본 검증 명령은 저장소 루트의 `npm run check`, `npm run build`, `npm run build:firefox`, `git diff --check`다.
