# 번역

확장은 고정 UI 현지화와 본문 기계 번역을 구분합니다. 고정 문구는 사이트 계약의 사전과 규칙으로 치환하고, 본문은 브라우저 내장 Translator API로 영어에서 한국어로 번역합니다.

## 처리 흐름

1. 페이지 adapter가 지원 DOM을 `DomTranslationTarget`으로 수집합니다.
2. `PageTranslationController`가 페이지·문맥·정책을 포함한 요청을 만듭니다.
3. 번역 정책이 이름·기술 표기와 문서 구조를 보호합니다. Forum Topic은 구조와 보호값을 로컬에 남기고 일반 텍스트 구간만 전달하며, 다른 페이지는 보호 토큰을 사용합니다.
4. `TranslationProvider`가 텍스트를 번역합니다.
5. 컨트롤러와 정책이 결과를 검증하고 `OriginalPreservingRenderer`가 원본 DOM을 보존한 채 번역문을 표시합니다.

원문·번역문·표시 기록은 페이지와 프레임 메모리에만 유지합니다. OFF 또는 종료 시 표시와 캐시를 정리하고 원문을 복원합니다.

## 대상과 표시 방식

| 모드 | 표시 |
| --- | --- |
| `block` | 설명·접근·댓글 블록을 번역하고 원문 보기·재번역을 제공합니다. |
| `inline-copy` | 원본과 같은 문맥에 번역 복사본을 배치하고 원문 보기·재번역을 제공합니다. |
| `inline` | 짧은 제목 등의 텍스트 노드를 치환합니다. OFF 시 복원하며 별도 원문·재번역 버튼은 제공하지 않습니다. |

지역·루트·사진·검색·포럼·도움말 등에서 실제 지원 DOM을 수집합니다. 루트 통계는 화면에 보이거나 가까운 등반 기록부터 번역합니다. 사용자·기여 목록·연락 페이지와 기여 폼은 고정 UI를 중심으로 처리합니다.

Help Hub의 기능 제안 제목·설명은 자동 번역과 원문 확인을 제공하고 작성자·투표 수·입력값을 유지합니다. 동적으로 추가되는 카드·댓글·모달은 기존 관찰 주기에서 처리하며 번역 복제본을 다시 수집하지 않습니다.

## 엔진 준비와 상태 안내

[ChromeTranslationProvider](../src/platforms/chrome/chrome-translation-provider.ts)는 실행 중인 콘텐츠 스크립트의 `globalThis.Translator`와 영어→한국어 가용성을 확인합니다. 브라우저 이름이나 페이지 자체의 API 노출 여부로 지원을 판단하지 않습니다.

| API 응답 | 처리 |
| --- | --- |
| `available`, `readily` | 준비 완료 |
| `downloadable`, `after-download`, `downloading` | 준비 필요 |
| API 부재, `unavailable`, `no`, 조회 예외 | 미지원 |

상단 스위치를 켜면 메인·본문 번역 지원 페이지에서 `Translator.create()`를 호출합니다. 사용자 활성화를 유지하도록 설정 저장이나 가용성 조회를 먼저 기다리지 않습니다. 준비와 번역은 같은 provider 인스턴스의 Promise를 재사용하며 생성 실패 후에는 다시 시도할 수 있습니다.

메인은 엔진 준비만 시도하며 본문 준비 안내·일반 클릭 재시도를 제공하지 않습니다. 본문 페이지에서 추가 사용자 동작이 필요하면 일반 클릭·키 입력으로 자동 재시도합니다. 팝업 ON은 설정을 전달하므로 본문 페이지에서 별도 클릭이 필요할 수 있습니다. 첫 실행 안내가 사라지는 것은 설정 저장 성공이며 모델 준비 완료와 별개입니다.

| 상태 | 사용자 화면 |
| --- | --- |
| 정상 번역 또는 대상 없음 | 엔진 안내를 표시하지 않습니다. |
| 다운로드·사용자 동작 필요 | 페이지를 계속 사용하면 자동 준비된다는 안내를 표시합니다. |
| 준비·재시도 중 | 준비 중 상태를 표시하고 중복 실행을 막습니다. |
| API 미지원 | 원문과 사용 안내를 표시합니다. 고정 UI·탐색 기능은 유지합니다. |
| provider 실패 | 원문 또는 보관된 번역을 유지하고 재시도를 안내합니다. |
| 포럼 일부 구간 실패 | 성공 구간은 번역문, 실패 구간은 원문 또는 이전 번역으로 표시하고 재시도를 제공합니다. |
| 토큰·구조 검증 실패 | 원문을 유지하며 문단·페이지 오류 안내는 표시하지 않습니다. |

안내는 문서당 하나를 본문 근처에 표시하고 접힌 섹션 안에 가두지 않습니다. 상태 문구는 `role=status`, `aria-live=polite`로 전달하며, 문단 오류가 이미 표시되면 같은 페이지 실패 안내를 생략합니다. 대상이 사라지거나 상태가 해소되면 제거합니다. 별도의 번역 준비 시작 버튼이나 확인할 수 없는 다운로드 백분율은 표시하지 않습니다. 외부 번역 서비스로 자동 전환하지 않습니다.

## 원문 보존과 재번역

Forum Topic 이외의 토큰 경로에서는 DOM에서 확인한 루트명·지역명·사용자명, 등급, URL, 이메일, GPS와 장비 규격을 요청별 토큰으로 보호합니다. 일반 등반 용어는 엔진이 문맥에 따라 번역하며 고정 한국어 치환을 강제하지 않습니다.

각 보호 토큰은 정확히 한 번 존재해야 합니다. 누락·중복·변형이나 알 수 없는 토큰, 토큰 경계에 붙은 불필요한 영문·숫자가 있으면 결과를 폐기합니다. 토큰 대소문자 차이만 허용하며 식별자 숫자를 추측해 보정하지 않습니다. URL 보호는 DOM 표식 사이의 실제 텍스트만 검사합니다. 링크 목적지·강조·목록·줄바꿈은 원본 DOM 구조를 유지합니다. 빈 결과나 원문과 같은 결과를 성공으로 표시하지 않습니다.

포럼 이외의 `재번역`은 해당 표시 영역의 캐시를 우회합니다. 처리 중에는 기존 번역을 유지하고, 달라진 결과는 한 번에 교체합니다. 같은 결과는 `동일한 결과`, provider 오류는 `재번역 실패`로 알립니다. 구조 검증이 거부한 결과는 원문을 유지하는 `preserved` 상태로 처리합니다.

포럼 이외의 긴 댓글은 루트 레벨 빈 줄을 기준으로 문단을 나누어 순서대로 번역하고, 모든 문단과 구조 검증이 성공한 뒤 표시합니다. 구조화된 본문의 토큰 검증이 실패하면 단일 줄바꿈까지 경계를 좁혀 한 번 재시도할 수 있습니다. 중첩 링크·강조·목록 안은 나누지 않으며 일부 구간만 성공한 결과를 표시하지 않습니다.

## Forum Topic의 본문과 부분 재시도

`forum-topic`의 구조화된 대상은 문단·목록·인용·강조 등 원본 구조 사이의 텍스트 구간을 번역한다. DOM 구조 표식과 URL·이메일·등급·확인된 이름 등 보호값은 로컬에서 결합하며 모델에 보내지 않는다. 문단, 줄바꿈, 연속 공백, 탭과 원래 링크 목적지를 유지한다. 긴 텍스트 구간은 최대 2,000 UTF-16 코드 단위로 나누고 surrogate pair를 끊지 않는다.

- 번역 성공 구간은 한국어로, 실패한 구간은 원문 또는 보관된 이전 번역으로 표시한다. 일부 실패를 전체 성공으로 기록하지 않고 `partial`, 실패 구간 수와 전체 구간 수를 남긴다.
- 조작 UI는 글당 하나의 원문 보기·재번역을 유지한다. 실패 구간마다 별도 버튼을 만들지 않는다.
- 실패 상태가 보관되어 있으면 재번역은 실패한 구간만 다시 호출한다. 완전히 성공한 글의 명시적 재번역은 전체 구간의 캐시를 우회한다.
- 성공한 구간만 캐시에 저장하며 부분 결과를 완성된 글의 캐시로 저장하지 않는다. 같은 문맥의 동일 텍스트 구간은 재사용한다.
- 순차 실행·화면 근처 대상 우선 처리를 유지한다. 구간 수가 늘어나므로 호출 수나 지연이 반드시 감소한다고 보장하지 않는다.
- 부분 재시도 상태는 별도 상한을 두고 전체 번역 캐시 문자 예산 안에서 보관한다. 한도 초과로 상태가 제거되면 이후 재번역이 더 많은 구간을 처리할 수 있다. OFF·destroy·원문 변경·연결 해제 때 이전 상태를 폐기한다.
- 원본 인용 작성자·서명·코드와 안전한 이미지, 글꼴·강조·정렬 등 허용된 작성 서식을 보존한다. 영상 복제는 HTTPS YouTube/Vimeo의 명시적 embed 경로에 한정하고 lazy loading·sandbox를 적용한다. 임의 iframe, script, 이벤트 속성이나 작성 폼은 복제하지 않는다.

이 경로는 특정 글 ID나 문장을 하드코딩하지 않는다. 실제 Chrome 모델의 문맥 품질은 텍스트 구간 분할의 영향을 받으므로 자동 구조 검사와 별도로 검증해야 한다.

## 입력·제출 데이터 보존

- 사용자가 작성한 `input`·`textarea` 값과 편집기 내용을 변경하지 않습니다.
- 폼 `action`, `method`, `name`, hidden 값과 submit 값을 유지합니다.
- 값이 없는 `option`의 텍스트는 제출값일 수 있으므로 유지합니다. Help Hub의 지정된 카테고리는 표시용 `label`만 번역합니다.
- 기여 폼과 동적으로 열린 개선 모달은 계약에 등록한 고정 안내·라벨·placeholder를 현지화하고 OFF 시 복원합니다.

## 부하와 수명주기

provider 호출은 컨트롤러의 단일 큐에서 순차 처리합니다. 준비 큐는 한 번에 최대 32개씩 꺼내고 이벤트 루프에 제어를 돌려줍니다. 댓글은 `IntersectionObserver`가 있으면 화면에 보이거나 가까운 대상부터 처리합니다.

프레임별 번역 캐시는 최대 500개이며 키·번역 합계가 393,216 UTF-16 코드 단위를 넘으면 오래된 항목부터 제거합니다. 포럼 부분 재시도 상태는 최대 500구간·131,072 코드 단위로 제한하여 두 보관 영역의 문자 예산 합계는 524,288 이내입니다. 성공한 글은 별도 부분 상태에서 제거합니다. 캐시 키에는 provider·언어·페이지·문맥·정책·용어집 버전과 입력을 포함합니다. 이 제한은 DOM·표시 기록·실행 중 데이터까지 포함한 전체 메모리 사용량의 상한이 아닙니다.

동적 DOM은 원문과 fingerprint로 변경된 대상만 처리합니다. OFF·종료 뒤 도착한 이전 작업의 결과는 화면이나 캐시에 반영하지 않습니다.

## 유지보수와 확인 범위

현재 번역 정책 버전은 `mpkr-policy-6`, 용어 정책 버전은 `mpkr-climbing-ko-3`이며 [정책 상수](../src/sites/mountain-project/contract/translation/glossary.ts)에서 관리합니다. 정책이나 보호 규칙을 바꾸면 캐시 키와 관련 회귀 테스트를 함께 확인합니다.

자동 테스트는 구조 보존·부분 실패 복구·동적 DOM·OFF 복원을 확인합니다. 실제 엔진의 번역 품질, 모델 다운로드와 사용자 활성화, 운영 사이트의 로그인·iframe 동작은 배포 후보로 별도 확인합니다. 텍스트 구간 분할은 호출 수와 문맥 품질에 영향을 줄 수 있습니다.
